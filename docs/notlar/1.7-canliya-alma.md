# 1.7 Canlıya alma (Vercel + Neon + Resend)

Bu adımda uygulamayı internete açıyoruz. Kod tarafı hazır; aşağıdaki
hesapları açıp ayarları girmek sana kalıyor. Hepsi ücretsiz planla çalışır ve
hiçbirinde kredi kartı gerekmez.

| Servis                       | Ne için                         | Ücretsiz plan      |
| ---------------------------- | ------------------------------- | ------------------ |
| [Vercel](https://vercel.com) | Next.js uygulamasını çalıştırır | Hobby              |
| [Neon](https://neon.tech)    | PostgreSQL veritabanı           | Free (0.5 GB)      |
| [Resend](https://resend.com) | E-posta gönderir                | Ayda 3.000 e-posta |
| Stripe                       | Ödeme (hâlâ test modunda)       | Test modu ücretsiz |

## Bu adımda koda eklenenler

| Ne                    | Nerede                                   | Neden                                                                                                                                                                           |
| --------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Gerçek e-posta        | `src/lib/email/`                         | `RESEND_API_KEY` varsa e-postalar Resend ile gönderilir, yoksa eskisi gibi terminale yazılır. Gönderim hata verirse kayıt akışı durmaz, hata loglanır.                          |

## Adım adım kurulum

Sıra önemli: önce veritabanı, sonra uygulama, en son da uygulamanın adresini
bilmesi gereken servisler (GitHub, Stripe).

### 1. Neon (veritabanı)

1. <https://console.neon.tech/signup> → **Continue with GitHub**.
2. **Create project**:
   - Name: `saas-s`
   - Postgres version: **17**
   - Region: **AWS Europe Central 1 (Frankfurt)**
3. Proje açılınca **Connect** butonuna bas. **Connection pooling** açık olsun
   (adreste `-pooler` geçmeli). Adresi kopyala:

   ```
   postgresql://neondb_owner:...@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

   Bu `DATABASE_URL`. Bir yere not et.

> **Neden "pooler"?** Vercel'de uygulama tek bir sunucuda değil, ihtiyaca
> göre açılıp kapanan birçok küçük fonksiyonda çalışır. Her biri ayrı
> bağlantı açarsa veritabanının bağlantı sınırı dolar. Pooler bu
> bağlantıları az sayıda gerçek bağlantıya toplar.

### 2. İki gizli anahtar üret

Kendi bilgisayarında, proje klasöründe iki kez çalıştır:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Birincisi `SESSION_SECRET`, ikincisi `CRON_SECRET`. Geliştirme ortamındaki
`.env` dosyandakini **kullanma**; canlının anahtarı başka olmalı.

### 3. Vercel (uygulama)

1. <https://vercel.com/signup> → **Continue with GitHub**. Hobby planı seç.
2. **Add New… → Project** → `AliKaracabey/saas-s` reposunu **Import** et.
   (Listede yoksa "Adjust GitHub App Permissions" ile repoya izin ver.)
3. **Project Name**: `saas-s` bırak. Adresin
   `https://saas-s.vercel.app` olacak. Bu ad alınmışsa Vercel sonuna bir ek
   koyar (ör. `saas-s-ali.vercel.app`); ekranda gördüğün adresi kullan.
4. Framework olarak Next.js'i kendisi bulur. Build ayarlarına dokunma
   (`vercel-build` script'ini kendisi kullanır).
5. **Environment Variables** bölümüne ekle:

   | Ad               | Değer                                                            |
   | ---------------- | ---------------------------------------------------------------- |
   | `DATABASE_URL`   | Neon'dan kopyaladığın adres                                      |
   | `APP_URL`        | `https://saas-s.vercel.app` (kendi adresin, sonunda `/` olmadan) |
   | `SESSION_SECRET` | 2. adımdaki birinci anahtar                                      |
   | `CRON_SECRET`    | 2. adımdaki ikinci anahtar                                       |

6. **Deploy**. Bir iki dakika sürer. Derleme loglarında
   `Migration'lar uygulandı.` satırını göreceksin.
7. Tarayıcıda `https://saas-s.vercel.app/api/saglik` aç → `{"ok":true}`.
8. Kayıt olmayı dene. E-posta henüz gitmez (Resend'i birazdan ekleyeceğiz);
   linki **Vercel → Project → Logs** sayfasında görebilirsin.

### 4. Resend (e-posta)

1. <https://resend.com/signup> → GitHub ile giriş.
2. **API Keys → Create API Key**, izin: "Sending access". Anahtarı (`re_...`)
   kopyala.
3. Vercel → Project → **Settings → Environment Variables**:

   | Ad               | Değer                            |
   | ---------------- | -------------------------------- |
   | `RESEND_API_KEY` | `re_...`                         |
   | `EMAIL_FROM`     | `saas-s <onboarding@resend.dev>` |

> **Önemli sınır:** Kendi alan adını (domain) doğrulamadan Resend sadece
> **hesabını açtığın e-posta adresine** gönderim yapar. Portföy demosu için
> bu yeterli: kayıt olurken o adresi kullan. İleride bir alan adı alırsan
> Resend → **Domains** sayfasından ekleyip DNS kayıtlarını girersin, sonra
> `EMAIL_FROM`'u `saas-s <bildirim@senin-alanin.com>` yaparsın.

### 5. GitHub ile giriş (isteğe bağlı)

1.3b'de oluşturduğun OAuth uygulaması `localhost`'a dönüyor. Canlı için
**ayrı bir tane** aç: GitHub → Settings → Developer settings → OAuth Apps →
**New OAuth App**

- Homepage URL: `https://saas-s.vercel.app`
- Authorization callback URL: `https://saas-s.vercel.app/giris/github/callback`

Client ID ve yeni bir Client Secret'ı Vercel'e `GITHUB_CLIENT_ID` ve
`GITHUB_CLIENT_SECRET` olarak ekle.

### 6. Stripe (isteğe bağlı, test modunda kalıyor)

Canlıda `stripe listen` yok; Stripe'ın webhook'ları doğrudan bize göndermesi
gerekiyor.

1. Stripe Dashboard (Test mode açık) → **Developers → Webhooks → Add
   endpoint** (yeni arayüzde **Add destination**).
2. Endpoint URL: `https://saas-s.vercel.app/api/stripe/webhook`
3. Olaylar:
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `customer.subscription.paused`
   - `customer.subscription.resumed`
4. Oluşturduktan sonra **Signing secret**'ı (`whsec_...`) kopyala. Bu,
   `stripe listen`'in verdiğinden farklıdır.
5. Vercel'e ekle: `STRIPE_SECRET_KEY` (`sk_test_...`),
   `STRIPE_WEBHOOK_SECRET` (bu yeni `whsec_...`), `STRIPE_PRICE_PRO`
   (`price_...`).

Test modunda kalmamızın nedeni: bu bir portföy projesi, gerçek para almak
şirket bilgisi ve vergi kaydı gerektirir. Ziyaretçiler `4242 4242 4242 4242`
kartıyla Pro'ya geçişi deneyebilir.

### 7. Yeniden deploy

Ortam değişkenleri sadece **yeni** derlemelerde geçerli olur. 4–6. adımlardan
sonra Vercel → **Deployments** → en üstteki derleme → **⋯ → Redeploy**.

### 8. Kontrol listesi

- [ ] `/api/saglik` → `{"ok":true}`
- [ ] Kayıt ol (Resend hesabının e-postasıyla) → doğrulama e-postası geldi
- [ ] Şifremi unuttum → e-posta geldi, şifre değişti
- [ ] Ekip aç, faturalandırma sayfası açılıyor
- [ ] (Stripe ekledinse) Pro'ya geç → test kartı → plan Pro oldu
- [ ] Vercel → Settings → **Cron Jobs** sayfasında `/api/cron/temizlik` görünüyor
- [ ] GitHub repo sayfası → sağdaki ⚙️ (About) → **Website**: canlı adresin

## Bundan sonra nasıl çalışıyor?

- `main`'e her merge → Vercel otomatik derler ve canlıya alır. Migration'lar
  derlemeden önce çalışır.
- Her PR → Vercel bir önizleme adresi üretir ve PR'a yorum olarak ekler.
  Önizlemeler canlı veritabanını kullanır ama migration çalıştırmaz. Bu yüzden
  şema değiştiren bir PR'ın önizlemesi, merge edilene kadar hata verebilir.
  Bu bilinçli bir tercih: canlı verinin güvenliği önizlemeden önemli. (Daha
  gelişmiş çözüm: Neon'un Vercel entegrasyonu her PR için ayrı bir veritabanı
  dalı açar.)
- Bir şey bozulursa: Vercel → **Deployments** → önceki çalışan derleme →
  **⋯ → Promote to Production**. Saniyeler içinde geri dönersin. (Veritabanı
  geri alınmaz; o yüzden migration'ları her zaman geriye uyumlu yazmak iyi
  bir alışkanlık.)
